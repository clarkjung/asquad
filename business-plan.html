How skills actually work — injection, not training

Claude is not fine-tuned or retrained. The skill's contents are injected into the context window on every API call. system.md becomes the system prompt. examples.jsonl becomes few-shot demonstrations. Claude reads them fresh each time and responds accordingly.

# What asquad sends to Claude on every call
anthropic.messages.create(
  system = system.md content,           ← provider's expertise
  messages = [
    ...examples from examples.jsonl,  ← few-shot demonstrations
    {"role": "user", "content": user_input} ← actual question
  ],
  tools = tools.json,                   ← external API calls
  model = skill.yaml → model field
)

Provider IP Protection

Your prompt is your product.
We protect it.

The biggest concern for expert providers: "What if someone copies my prompt?" asquad's answer is a multi-layer protection system — technical, legal, and economic.

⚠ The Real Risk

Skills are system prompts injected into Claude at runtime — not trained into a model. In theory, a sophisticated consumer could try to reverse-engineer the prompt by observing many outputs. This is the honest vulnerability we must address.

🔐

Layer 1 — Prompt Encryption

All skill prompts are encrypted at rest (AES-256). The raw prompt text is never exposed to consumers — not in API responses, not in error messages, not anywhere. Consumers only receive the output, never the system prompt.

# What consumers see via API
GET /api/v1/agents/{id}
→ {
  "name": "Contract Reviewer",
  "description": "...",
  "skill_prompt": null  ← never exposed
}
🔒

Layer 2 — Private Mode

Providers choose: Public (listed on marketplace, prompt hidden) or Private (unlisted, invite-only API access). Enterprise providers can keep skills completely off the public marketplace and share only with approved consumers.

PUBLIC
Listed on marketplace. Anyone can call via API. Prompt encrypted and hidden. Great for broad distribution.
PRIVATE
Unlisted. Only consumers you approve can access. Perfect for enterprise/B2B skill licensing.
📋

Layer 3 — Terms of Service + Legal

Consumer ToS explicitly prohibits reverse-engineering, prompt extraction, or reproduction of skill behavior. Violations result in immediate API key revocation and legal liability. asquad acts as the enforcement layer between provider and consumer.

⭐

Layer 4 — Reputation Moat (Economic)

Even if someone copies a prompt, they can't copy the reputation. A skill with 500 five-star reviews from verified users is worth infinitely more than an unverified copy. Reviews, usage count, and provider verification create an economic moat that's impossible to clone.

🔄

Layer 5 — Continuous Versioning

Providers can update their skill anytime. v1.0 → v1.1 → v2.0. Consumers always call the latest version automatically. A copied prompt becomes outdated the moment the original is improved. The provider who keeps iterating always stays ahead.

The honest truth about prompt protection

No system can make a prompt completely uncopyable — just like no system makes software completely uncrackable. But the combination of encryption + legal ToS + reputation + versioning makes copying economically not worth it. The provider who builds reputation and keeps improving will always outcompete any copier.
